# בית · רשימת קניות

אפליקציית ווב (PWA) לרשימת קניות משותפת: קטלוג מוצרים, רשימה לפי חנות ולפי סדר המסלול בחנות,
מצב קנייה, ייבוא קבלות דיגיטליות של רמי לוי והשוואת מחירים מתוך הקבלות.

הכול נשמר קודם בטלפון, ולכן האפליקציה עובדת גם בלי קליטה וגם כשהשרת במצב שינה.
כשיש חיבור, השינויים עולים לשרת ומגיעים לטלפון השני.

## קבצים

- `index.html`, `styles.css`: המעטפת והעיצוב
- `js/app.js`: המסכים
- `js/logic.js`: הרשימה, מצב קנייה, התאמת קבלה, מחירים והצעות
- `js/store.js`: שמירה בטלפון וסנכרון עם Supabase
- `js/categories.js`: הקטגוריות וזיהוי קטגוריה לפי שם
- `js/receiptText.js`: קריאת קבלה של רמי לוי מהטקסט שהועתק מעמוד הקבלה
- `js/seed.js`: נתוני ההתחלה: הקבלה מרמי לוי מ-12/10 והרשימה הנוכחית
- `config.js`: פרטי החיבור ל-Supabase
- `supabase/schema.sql`: מבנה הנתונים וכללי הגישה
- `.github/workflows/keepalive.yml`: פנייה לשרת כל 3 ימים כדי שלא ייכנס למצב שינה
- `manifest.webmanifest`, `sw.js`, `icons/`: התקנה למסך הבית ועבודה בלי אינטרנט

## הרצה במחשב

```
python3 -m http.server 5190
```

ואז לפתוח את http://localhost:5190

## חיבור לסנכרון (פעם אחת)

כבר בוצע ב-25/10/2026 עבור הפרויקט **bayit** ב-Supabase (אזור אירופה). הפרטים נמצאים ב-`config.js`.
השלבים כאן נשארים לתיעוד, או למקרה שצריך להקים מחדש.

1. **פרויקט ב-Supabase.** אפשר להשתמש בחשבון הקיים: פרויקט חדש או קיים.
2. **התחברות בלי סיסמה.** ב-Authentication, בהגדרות ה-Sign In / Providers, מפעילים את
   **Allow anonymous sign-ins**. כל טלפון מקבל זהות משלו, ומשק הבית מחבר ביניהם עם קוד.
3. **מבנה הנתונים.** ב-SQL Editor פותחים שאילתה חדשה, מדביקים את כל התוכן של `supabase/schema.sql` ולוחצים Run.
4. **פרטי החיבור.** ב-Project Settings → API מעתיקים את **Project URL** ואת המפתח **anon public**
   ומדביקים אותם ב-`config.js`. המפתח הזה נועד להיות גלוי. ההגנה על הנתונים היא כללי הגישה מהשלב השלישי:
   רק מי שהצטרף למשק הבית רואה את הנתונים שלו.

## העלאה לאינטרנט (נדרש HTTPS כדי להתקין בטלפון)

**GitHub Pages** (מומלץ, כי שם רץ גם ה-keep-alive):
1. יוצרים מאגר (repository) חדש ב-GitHub ומעלים אליו את כל הקבצים בתיקייה, כולל התיקייה `.github`.
2. ב-Settings → Pages בוחרים Deploy from a branch, הענף `main`, התיקייה `/ (root)`.
3. אחרי דקה-שתיים האפליקציה זמינה בכתובת `https://<שם-המשתמש>.github.io/<שם-המאגר>/`.

אפשר גם Netlify Drop כמו באפליקציית "מעגלים", אבל אז ה-keep-alive צריך לרוץ ממאגר ב-GitHub או מ-cron-job.org.

## שמירה על השרת ער

Supabase בחינם נכנס למצב שינה אחרי כשבוע בלי פעילות. הקובץ `.github/workflows/keepalive.yml` פונה אליו כל 3 ימים.
1. במאגר ב-GitHub: Settings → Secrets and variables → Actions → New repository secret. מוסיפים
   `SUPABASE_URL` ו-`SUPABASE_ANON_KEY` (אותם ערכים כמו ב-`config.js`).
2. בלשונית Actions מפעילים את ה-workflow ומריצים אותו פעם אחת ידנית (Run workflow) כדי לוודא שהוא עובר.

שימו לב: GitHub עוצר workflows מתוזמנים במאגר שלא היה בו שום שינוי 60 יום, ושולח על כך מייל.
מספיקה לחיצה אחת כדי להפעיל אותו מחדש. וגם אם השרת נרדם, האפליקציה ממשיכה לעבוד ומסתנכרנת כשמעירים אותו
בלוח הבקרה של Supabase.

## התקנה בטלפון

- **אייפון:** פותחים את הכתובת ב-Safari ← כפתור השיתוף ← "הוספה למסך הבית".
- **אנדרואיד:** פותחים ב-Chrome ← "התקנת האפליקציה".

## משק הבית

1. בטלפון הראשון: הגדרות ← "יצירת משק בית". הקטלוג והרשימה מהטלפון הזה עולים לשרת.
2. ההגדרות מציגות קוד הצטרפות בן 6 תווים, ויש כפתור לשליחת הזמנה.
3. בטלפון השני: הגדרות ← מזינים את הקוד ← "הצטרפות". הנתונים של משק הבית יורדים לטלפון.

## ייבוא קבלה

1. פותחים את הקישור לקבלה מה-SMS.
2. בעמוד הקבלה לוחצים "הצגת עוד פריטים", כדי שכל הפריטים יופיעו.
3. לחיצה ארוכה על הטקסט ← "בחר הכל" ← "העתק".
4. באפליקציה: קבלות ← "הדבקה". האפליקציה קוראת את הקבלה ומציגה את ההשוואה לרשימה.

באנדרואיד אפשר גם לשתף את הטקסט המסומן ישירות לאפליקציה (אחרי שהיא מותקנת).

הקריאה נעשית בטלפון עצמו ולא דרך שרת, ולכן היא עובדת גם כשאין חיבור לסנכרון.
נתמכות כרגע הקבלות הדיגיטליות של רמי לוי. מהקבלה נשמרים רק המוצרים, הכמויות, המחירים, הסניף והתאריך,
ולא שם, טלפון או פרטי תשלום.

למה לא פשוט להדביק את הקישור: רמי לוי חוסמים פניות אוטומטיות מהשרתים לעמודי הקבלה,
ולכן הקבלה נקראת מהעמוד שפותחים בעצמכם.

## מחירים

מוצג רק מחיר שיש לו מקור: קבלה שיובאה, עם התאריך שלה. במקום שאין מחיר כתוב "אין נתון".

## עדכון גרסה

אחרי שינוי בקבצים מעלים את המספר ב-`VERSION` שב-`sw.js` (למשל `bayit-v2`), כדי שהטלפונים יורידו את הגרסה החדשה.

## אם שני אנשים משנים את אותו פריט באותו זמן

נשמר השינוי האחרון שהגיע לשרת. ברשימת קניות זה כמעט לא קורה, ובמקרה הגרוע כמות אחת תתעדכן פעמיים.
